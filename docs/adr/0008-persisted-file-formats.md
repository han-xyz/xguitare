# The files xguitare reads back are strict TOML and 32-bit float mono WAV, and only `project.toml` carries a `format` number

xguitare reads back four kinds of file it writes, all in `crates/xguitare-core`. A Project is a folder with `project.toml` and `project.autosave.toml` (one read and write path, `Project::load`, `Project::load_autosave`, `Project::save`, `Project::save_autosave` in `project.rs`) and its Takes under `takes/`. A Preset is one TOML file in the Bank directory (`Preset::parse` in `preset.rs`). The Daemon's `state.toml` holds the choices made through the Control API (`SavedState` in `state.rs`). A Take is a WAV file of the dry input, 32-bit float, mono, at the Project's sample rate (`TakeWriter` in `take_writer.rs`). Two more kinds are written and are not formats this decision covers: a Render, a stereo WAV of 16-bit or 24-bit integer or 32-bit float samples (`wav_spec` in `render.rs`), written for the user and never read back; and, at first run, the starter Bank's Preset files and a mono 32-bit float Cabinet IR WAV (`firstrun.rs`), which from then on are Presets like any other and a Cabinet IR read as any WAV a user supplies. Every TOML reader refuses a key it does not know (`deny_unknown_fields`), so a typo in a hand-edited file is an error at its line, not a value silently left at its default. `project.toml` and the autosave start with `format = 1`. A reader first reads only `format`, in a pass that ignores every other key; a missing `format` is 1, the files written before the key; a `format` above 1, however large, is refused with `project format <n> is newer than this xguitare (reads up to 1)` before the strict parse, so a file from a newer build is never refused by one of its new keys instead; a `format` of 0, below 0 or not a whole number is refused with `project format must be a whole number of 1 or more`. Because the strict reader refuses unknown keys, `format` goes up whenever a build that knows only the old number could not read the file: a key added, removed or changed in meaning. This differs from the Control API's `PROTOCOL_VERSION` (ADR-0006), which does not go up for an addition. Presets, `state.toml` and Take files carry no format number. A choice Parameter's number in a Preset is its position in the Module's label table, so label tables only grow at the end.

Considered and rejected: a format number in Presets and `state.toml` too (Presets are short files people write and share by hand, and `state.toml` is rewritten by the Daemon itself, which starts from its defaults with a warning when it cannot read the file; neither needed one yet); copying the protocol's rule that additions are free (false here: a build that refuses unknown keys cannot read a file with an added key, so an addition must raise `format`); dropping `deny_unknown_fields` so that newer files load in older builds (a misspelt key in a hand-edited Project would then be ignored without a word).

What it costs. A build older than this change refuses a `project.toml` that has the key, with an unknown-field error naming `format`, because it reads no `format`; a Project saved by this build is not opened by an older one. Every key added to `project.toml` raises `format`, so an older build refuses the newer file even when it could have ignored the new key. A newer Preset or `state.toml` gives an older build an unknown-key error with no hint that the file is newer.
