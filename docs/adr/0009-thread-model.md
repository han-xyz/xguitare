# The Daemon's threads share one `Mutex<EngineState>`, the audio thread reaches them only through lock-free queues, and `project_open` reads its files outside that lock

The Daemon runs these threads. The JACK process callback (the audio thread) runs the Rack and the Arrangement; it takes no lock and talks to the rest only through the `rtrb` ring buffers in `crates/xguitare-core/src/engine.rs` (`EngineQueues` on the other side: Commands in, retired Racks and Arrangements, peaks and Take audio out) and the atomics of `EngineShared`. The thread `control` accepts Control API connections (`crates/xguitare/src/socket_server.rs`), and each connection gets a thread `control-<n>` that reads one request line at a time. The Daemon's main thread runs the poll loop (`watch_until_stopped` in `crates/xguitare/src/daemon.rs`): every 100 ms it follows sample-rate changes, ticks the Tuner, applies Bank changes and MIDI program changes, carries out the Project events and autosaves. Each open Project has a thread `disk` (`DiskThread`, `crates/xguitare/src/disk_writer.rs`) that writes Take files and reads the Take audio the Arrangement plays; it shares only queues and the `WritingTakes` list with the rest. A Render runs on a thread `render` of its own and shares only its `RenderJob`, whose status has a lock of its own. All Daemon state the Control API reads or changes is one `EngineState` behind one `Mutex`, held by a connection thread for the whole of one request (but `project_open`, below) and by the poll loop for one tick; the disk and render threads never take it.

A connection thread parses its request line before it takes the lock (`control::parse_line`). A `project_open` is then answered in two phases: under the lock, `project_control::begin_project_read` refuses it as the one-phase path would (a Project open or still closing) or returns a `ReadTicket` with `projects_dir`, the name, `restore` and the counter `Projects.generation`; with the lock released, `project_control::read_project` reads `project.toml` or `project.autosave.toml` and decodes each Item's active Take; under the lock again, `control::handle_request` installs that read. `generation` counts every Project open (`project_open`, `project_new`), every close (`project_close`, `close_for_stop`) and every `finish_closed`, so the install refuses when a Project is open or closing again, and reads once more under the lock when `generation` or `projects_dir` changed since the ticket: a Project another connection opened, changed, saved and closed in between is read as saved, and a read from an old `projects_dir` is never installed. It is a different counter from the Revision, which clients see; `generation` stays inside the Daemon. Every reply, `warnings` entry, error text and `code` is the one the one-phase path gives, which `control::handle` and `control::handle_line` still take.

Considered and rejected: one thread that owns `EngineState` and answers requests sent to it as messages (it would rewrite the signature of every request handler, and a long request would still hold up every other client); a second lock for the Projects part of the state (the poll loop takes both parts in one tick, so every path would need a fixed lock order, and a request that crosses both, such as `load` on a Track, would still take the two).

What it costs. Other work still runs under the lock and holds up every other client and the poll loop for as long as it takes: loading a Cabinet IR when a Rack is built (`build_rack`, through `Preset::build`, calls `ir::load_ir`), decoding Takes for an edit or an undo (`apply_items` and `restore_track` call `missing_takes`, and `add_finished_takes` decodes each finished Take in the poll loop), the poll loop's autosave (`autosave_if_due`) and the `project.toml` that `finish_closed` saves after the last Takes of a closed Project. A `project_open` that finds the state changed after its read reads the files a second time, under the lock. The second phase compares the ticket's `projects_dir` and `generation` only, so a write to the Project's folder by another process between the two phases is installed as read.
